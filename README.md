# Comparing Three Language Models: Bigram vs LSTM vs Transformer

## 1. What NLP task did I solve?

**Character-level language modeling:** given the previous characters of a text, predict the next character. All three models are trained and evaluated on exactly this task, on the same data.

## 2. Dataset

**Tiny Shakespeare**: about 1.1 million characters of Shakespeare's plays (65 distinct characters), from Andrej Karpathy's [`char-rnn`](https://github.com/karpathy/char-rnn) repository.

- **Download:** the notebook downloads it automatically to `data/input.txt`. To download manually:
  ```bash
  mkdir -p data
  curl -o data/input.txt https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt
  ```
- **Split:** first 90% for training, last 10% for validation (a contiguous split, so validation scenes are unseen).
- **Preprocessing:** none. Case, punctuation, and line breaks are kept so the models can learn the play format.

## 3. The three models

| Model | Context it uses | Size | How it works |
|---|---|---:|---|
| **Bigram** | Only the current character | 4,225 params | A 65 × 65 table of next-character logits. |
| **LSTM** (non-transformer) | All previous characters in the 128-char window, compressed into one hidden state | 946,625 params | 2-layer LSTM (embedding 128, hidden 256); gates control what the cell state keeps and forgets. |
| **Transformer** | All previous characters in the 128-char window, each reachable directly | 826,433 params | 4 blocks, 4 heads, width 128: token + positional embeddings, causal self-attention, feedforward, residuals, LayerNorm, output layer. |

**Bigram.** It uses only which character is current, so it learns letter-pair statistics (for example `q → u`) but ignores everything earlier: it cannot spell words longer than two letters, keep track of grammar, or follow the speaker/line structure of a play. In my run it reached a validation loss of 2.481, essentially the same as the closed-form count-based bigram (2.486), so this is the ceiling for any bigram model. Its sample shows the limit clearly: word-shaped fragments like "CEThef trid owind", with only short common words such as "my", "he", and "the" spelled correctly.

**LSTM.** It reads the context left to right and carries a hidden state forward, so it can use far more context than the bigram model, which is what lets it learn spelling, common words, and line breaks. It still struggles with long dependencies because all of the past has to be squeezed into one fixed-size state that is updated at every step, and it cannot directly look back at a specific earlier character. In my run it was the best model: validation loss 1.488, with a sample that uses real character names (PAULINA, ROMEO, MENENIUS) in the correct `NAME:` format and mostly real words.

**Transformer.** Self-attention lets every position compare itself with every earlier position in the window and pull information directly from the most relevant ones, instead of relying on information surviving many recurrent steps. Positional embeddings tell it the order of characters, since attention by itself is order-blind. In my run it reached a validation loss of 1.637, between the bigram and the LSTM. It learned the play format (`Clown:`, `JOHN OF AUMERLE:`) but produced more invented words than the LSTM, and its loss was still falling when training stopped.

## 4. Fair comparison

All three models use the same data split, vocabulary, batch size (64), number of training steps (3,000), gradient clipping, random seed, and **the same fixed evaluation windows**. Training time counts only optimisation steps. The LSTM and transformer have similar parameter counts (~0.9M) and the same 128-character context. The only intentional difference is the learning rate: 1e-2 for the bigram table (a single linear layer, which otherwise does not converge within the budget) and 1e-3 for the two neural models. As a check, the trained bigram model is compared with the closed-form count-based bigram, which it should match; it did (2.481 vs. 2.486).

## 6. Analysis

**Which model performed best?**
The LSTM, with a validation loss of 1.488 (perplexity 4.43), followed by the transformer at 1.637 (perplexity 5.14) and the bigram at 2.481 (perplexity 11.95). Both neural models cut the bigram's loss by more than a third. The LSTM also had the largest gap between training and validation loss (0.23, vs. 0.20 for the transformer), so it was starting to memorize the training text more.

**Which model trained fastest?**
The bigram, by far: 4.6 seconds in total, and its loss was within 0.03 of its final value by step 750. The LSTM took 74 seconds and the transformer 96 seconds, about 1.3 times as long per step as the LSTM. The transformer also learned more slowly per step: at step 250 its validation loss was 2.36 vs. 1.96 for the LSTM, and it was still dropping noticeably at the end (0.029 over the last 500 steps, about twice the LSTM's 0.015).

**Which model generated the most realistic text?**
The LSTM. Its sample uses real character names from the plays (PAULINA, ROMEO, HENRY BOLINGBROKE, MENENIUS), puts them in the correct `NAME:` format, and most words are real ("I will not be sworn to again the king"). The transformer also learned the format (`Clown:`, `JOHN OF AUMERLE:`) and line lengths, but it produces more invented words ("gatests", "abself", "Englanded") and repetitive filler ("and be not and be"). The bigram produces word-shaped fragments ("CEThef trid owind") with only short common words like "my", "he", and "the" coming out right.

**What did the transformer improve compared to the other models?**
Compared to the bigram, a lot: the loss-by-context plot shows the transformer's loss dropping from 2.545 with one character of context to 1.697 with 8 and 1.586 with 32, while the bigram stays flat around 2.48 because it can't use more than one character. Compared to the LSTM, it did not improve in this run. The two curves are almost identical for the first 3–4 characters, but then the transformer levels off around 1.59 after about 30 characters while the LSTM keeps improving to 1.44. So in this small, short training run, the transformer did not get extra value out of long context. Its advantage over the LSTM was mainly that its behavior is easier to inspect (see question 6).

**Was the improvement worth the added complexity?**
Over the bigram, clearly yes: a 0.84 drop in validation loss turned letter soup into recognizable Shakespeare-style text. The transformer over the LSTM was not worth it at this scale: it was more code, about 30% slower to train, and gave a worse loss with a similar number of parameters. One likely reason is that 3,000 steps with a constant learning rate and no warmup is too short for the transformer, since its loss was still falling twice as fast as the LSTM's at the end. Another is that character-level text depends mostly on the last few characters, which an LSTM handles well. A longer run would be the next experiment to see if the transformer catches up.

**What did attention improve, and what did I learn about it?**
The four heads in the last layer learned clearly different jobs. Head 0 is almost a single bright diagonal just below the main diagonal: each position mostly looks at the character right before it, a local, bigram-like pattern. Head 1 has a bright vertical stripe: after the line break in "this I know,\nShe is not for your turn", almost every position in the new line attends to the start of that line, which gives the model a way to track where it is in a line (useful for knowing when to break). Heads 2 and 3 spread their attention over a few recent characters, with brighter spots at spaces and punctuation, which looks like tracking the start of the current word. Attention is not just a blur of "look at everything": each head learns its own rule about which earlier characters matter, and you can see it. attention cut the loss from 2.48 to 1.64 compared to the bigram by using context, but didn’t beat the LSTM in this run.

## 7. What I learned

More context helps a lot, but at this scale only up to a point: most of the improvement over the bigram came from the first 8 characters of context, and both neural models gained little beyond about 30. A more advanced architecture does not automatically win. The transformer needs enough training to pay off, and in a short run on a small dataset an LSTM of the same size beat it. I also learned that attention heads are readable: each one learns its own pattern, which makes the transformer easier to inspect than the LSTM's hidden state. Finally, a sanity check like comparing the trained bigram to the count-based bigram is a simple way to confirm the training pipeline works.

## 8. Final reflection

**After comparing bigram, non-transformer, and transformer models, what do you think makes transformers powerful for language modeling?**

I think what makes transformers powerful is that attention gives every position a direct path to any earlier position, and the model learns which ones to use. The bigram model can't look back at all, and the LSTM has to squeeze everything it has read into one hidden state that is rewritten at every step. Attention instead lets each prediction pick out the characters that matter, and different heads learn different rules: in my heatmaps one head copies the previous character while another keeps pointing at the start of the current line. Because all positions are processed at once rather than one after another, this design can also be scaled to much larger models and datasets than an LSTM can. My results also showed the other side: with about 800K parameters and 3,000 training steps, the LSTM still won, and the transformer stopped benefiting from context after about 30 characters. So attention is not automatically better. Its strength shows up when there is enough data, model size, and training for it to learn which connections matter.
